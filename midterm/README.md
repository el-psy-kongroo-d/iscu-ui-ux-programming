# 중간시험: 데브플랜

7주차의 단계별 설정·확인 흐름을 개발 학습 계획 서비스로 바꾸고, 설정이 끝난 계획을 목록에 추가하여 다시 열거나 취소하는 경로를 구현했습니다. 문구 변경과 별개로 계획 배열, 목록 갱신, 개별 계획 조회, 취소 확인과 빈 목록 처리를 추가했습니다.

## 서비스와 사용자

- 주요 사용자: 개발 공부를 시작하는 학생과 초보 개발자
- 목적: 오늘 공부할 내용을 작은 단위로 정하고, 정해 둔 계획을 다시 확인하기
- 주요 행동: 학습 주제 입력 → 시간·복습 선택 → 확인 → 내 계획에 추가 → 다시 열기 또는 취소

발표 훈련 주제와 녹음 동의를 제거했습니다. `week7` 원본은 보존하고, 해당 폴더의 `index.html`, `style.css`, `script.js`를 복사해 이 폴더에서 이어서 수정했습니다. 기존 테마·탭·입력 검사·설정 확인은 새 기능으로 계산하지 않습니다.

## 추가한 경로와 조건

새 경로는 기존 설정 흐름의 **끝**, 설정 완료 화면에 연결했습니다.

| 사용자 행동 | 확인할 조건 | 화면 반응 | 다음 행동 |
| --- | --- | --- | --- |
| 학습 주제 입력 후 다음 | 공백을 제외한 주제가 있는가 | 비어 있으면 오류 안내와 입력창 포커스, 있으면 조건 단계로 이동 | 주제를 입력하거나 시간 선택 |
| 학습 시간·복습 선택 | 시간 15·30·60분, 복습 선택 시 문제 수 1·2·3개 | 선택한 값이 확인 화면에 표시됨 | 수정하거나 설정 완료 |
| 내 계획에 추가하기 | 설정한 주제가 있고 이번 계획을 아직 추가하지 않았는가 | 목록과 개수 갱신, 성공 안내, 추가 버튼 비활성화 | 다시 열기 또는 새 계획 만들기 |
| 목록의 다시 열기 | 누른 항목의 ID에 해당하는 계획이 있는가 | 해당 계획의 주제·시간·복습 수를 팝업에 표시 | 목록으로 돌아가기 또는 Escape |
| 계획 취소 | 해당 계획이 있는가, 취소를 확정했는가 | 확정하면 해당 항목만 제거하고 개수·안내 갱신 | 다른 계획 열기 또는 새 계획 만들기 |
| 계획 유지하기 또는 취소 팝업에서 Escape | 취소 확정 전인가 | 팝업을 닫고 목록을 그대로 유지 | 기존 계획 이용 |
| 목록이 비어 있음 | 계획 수가 0인가 | 빈 목록 설명과 첫 계획 만들기 버튼 표시 | 설정 시작 |
| 이전·수정 | 아직 설정 중인가 | 입력과 선택 유지 | 값을 수정하고 다시 확인 |
| 새 계획 만들기 | 새 설정을 시작하는가 | 주제·시간·복습·오류·추가 여부 초기화, 기존 목록 유지 | 다른 주제 입력 |

추가한 계획은 당시 설정의 복사본입니다. 새 계획을 편집해도 이전 계획은 바뀌지 않습니다. 주제는 `textContent`로 표시하며 HTML로 해석하지 않습니다.

## 실행과 검사

저장소 루트에서 다음 명령을 실행합니다.

```sh
python3 -m http.server 8000
node --check midterm/script.js
```

- 서비스: <http://localhost:8000/midterm/>
- 브라우저 자동 검사: <http://localhost:8000/midterm/tests.html>

`tests.html`은 실제 페이지를 iframe으로 열어 버튼 이벤트와 화면 결과를 검사합니다. 각 검사 결과와 통과 개수가 화면에 표시됩니다. `tests.html?width=320`, `?width=390`, `?width=768`, `?width=1100`으로 너비를 바꿔 재실행할 수 있습니다. 개발용 검사 페이지이므로 서비스 메뉴에는 연결하지 않았습니다.

테스트 과정에서 모바일 버튼 순서가 CSS의 `column-reverse` 때문에 뒤집히는 문제를 발견했습니다. 조회 버튼이 취소보다 먼저 보이도록 수정하고 위치를 확인하는 검사를 추가했습니다. 다크 테마의 모바일 조회 화면과 키보드 조작도 직접 확인했습니다.

추가 완료 후 상단 버튼으로 새 계획을 시작하면 이전 값이 남는 문제를 발견했습니다. 새 계획 시작 시 초기화하도록 수정한 뒤, 두 번째 계획 추가와 이전 계획 보존 검사를 다시 통과했습니다.

## 프로토타입 범위

서버나 계정 없이 브라우저 메모리에만 계획을 보관합니다. 새로고침하면 목록이 초기화되며, 이 제한을 화면에도 안내합니다. 복습 문제 자동 생성과 실제 학습 진행 측정은 구현하지 않았습니다. 핵심 행동에 집중하도록 이전 코드의 이메일 신청 영역을 제거했습니다.

HTML은 화면 구조, CSS는 표시 상태와 반응형 배치, JavaScript는 이벤트·입력 검사·계획 배열·화면 갱신을 담당합니다.

## 제출 전 직접 확인할 순서

1. 로컬 페이지에서 ‘학습 계획 만들기’를 누르고 안내를 확인합니다.
2. 주제를 비워 둔 채 다음으로 이동해 오류를 확인하고, ‘세션과 쿠키’를 입력합니다.
3. 60분·복습 3개를 선택한 뒤 확인 화면에서 값을 확인합니다.
4. 설정을 완료하고 ‘내 계획에 추가하기’를 누릅니다. 목록 개수와 성공 안내를 확인합니다.
5. ‘다시 열기’로 같은 주제·시간·복습 수가 나오는지 확인합니다.
6. 다른 계획을 추가한 뒤 이전 계획 내용이 유지되는지 확인합니다.
7. 취소 팝업에서 ‘계획 유지하기’와 Escape를 각각 시험하고, 마지막에는 취소를 확정합니다.
8. 모든 계획을 취소한 뒤 빈 목록의 버튼으로 새 계획을 시작합니다.
9. 모바일에서 버튼·입력·팝업을 확인하고 자동 검사 페이지의 결과를 확인합니다.
10. 로컬 확인을 마친 뒤 변경을 커밋·푸시하고, 배포 페이지와 이 README의 반영 상태를 다시 확인합니다.
